# 查询写法：中文检索的暗坑

**大多数「搜不到」是写法问题，不是信息不存在。** 中文搜索引擎的分词、纠错、去符号会把你的精确意图揉碎。

## 一、四个杠杆

### 1. 加限定词（最有效）

单搜名字几乎必然失败；名字 + 一个稳定属性，命中率能翻几倍。

| 想查 | 写法 |
| --- | --- |
| 基本确认 | `张伟 杭州 程序员` / `张伟 浙江大学` |
| 学校 | `张伟 浙江大学 2021` / `张伟 浙大 计算机` |
| 单位 | `张伟 阿里 后端` / `张伟 某某公司 招聘` |
| 事件 | `张伟 比赛 一等奖` / `张伟 论文` |
| 昵称 | `雾港信箱 B站` / `雾港信箱 微博` |
| 号码 | 号码加引号或直接搜号码（长数字串切分少，命中率高） |

### 2. 换形（同名不同形）

- 简体 / 繁体：`罗翔` / `羅翔`
- 全角 / 半角：`ＡＢＣ` / `ABC`
- 符号：`雾港_信箱`、`雾港-信箱`、`雾港·信箱`、`雾港 信箱`
- 拼音：`luoxiang`、`luo xiang`、`lx`、`luoxiang1997`
- 后缀数字：`昵称1`、`昵称2`、`昵称_`、`昵称2024`（大小号常见）
- 谐音/换字：`小胖`→`小胖纸`、`阿杰`→`阿杰丶`
- 姓名的常见笔误：`张玮`/`张炜`

脚本能生成一批：`shiji.py variants "雾港信箱"`；拼音和谐音**要你自己补**（模型比脚本擅长）。

### 3. 换引擎（结果差异很大）

同一个词，Bing / 360 / 搜狗微信 / DDG 返回的重合度往往不到一半。

```bash
python scripts/shiji.py search "关键词" --engine bing
python scripts/shiji.py search "关键词" --engine 360
python scripts/shiji.py search "关键词" --host zhihu.com   # 只要某站
```

### 4. 换层级（索引 → 正文）

搜索引擎给你标题+摘要；B站接口给你签名+投稿；公众号给你标题+摘要+账号。**每往下一层，信息量涨一个数量级**，但要付出打开页面的成本。

## 二、中文特有的坑

| 坑 | 表现 | 对策 |
| --- | --- | --- |
| **分词** | 搜「雾港信箱」被拆成「雾港 / 信箱」，返回一堆无关话题 | 用长尾组合（加平台名、加城市）；或直接搜更长的原句片段 |
| **两字生僻词被拆成单字** | 实测：搜「炜梦」返回的全是「炜」的字典页（百科/汉典/字典），一条「炜梦」都没有；加引号 `"炜梦"` **也没用**（Bing 不认引号） | 换搜狗微信（对短词分词更准，实测直接命中同名公众号）；或加限定词「炜梦 公众号 / 炜梦 公司」 |
| **纠错** | 生僻字被自动改成常用字（`耒阳`→`来阳`） | 加引号、加「不是」排除词、换引擎 |
| **`site:` 不生效** | Bing 宣称支持，但结果混入其他站 | 不依赖语法，改用 `--host` 在结果层硬过滤 |
| **引号不稳定** | 中文引号常被忽略（实测 Bing 对 `"炜梦"` 与 `炜梦` 返回完全相同） | 改用「词 + 词 + 词」的长组合 |
| **相关搜索污染** | 结果页混入「其他人还搜了」 | 只取结果区，别把推荐词当结论 |
| **时间不可控** | 多数引擎不支持精确时间过滤 | 关键词里带年份（`2021`、`2023级`） |
| **同名** | 一个名字几万人 | 三件套：姓名+单位/学校+城市 |

## 三、按种子类型的查询模板

```
昵称：      昵称 | 昵称 B站 | 昵称 微博 | 昵称 游戏 | 昵称 学校
姓名+单位： 姓名 单位 | 姓名 单位 招聘 | 姓名 单位 电话 | 单位 姓名 公示
姓名+学校： 姓名 学校 | 姓名 学校 学院 | 姓名 学校 获奖 | 姓名 学校 毕业
手机号：    号码 | 号码 微信 | 号码 招聘 | 号码 快递
邮箱：      邮箱 | 邮箱 github | 邮箱 论文
QQ群：      群号 | 群号 QQ群 | 群号 加群
照片：      无文字 → 图片反查（人工）；有文字 → OCR 后再搜文字
事件：      事件 时间线 | 事件 官方通报 | 事件 反转 | 事件 当事人
```

## 四、什么时候该停

- 连续两条查询返回的是同一批结果 → 换引擎或换词形，别再重复。
- 结果全是营销号/搬运号 → 追最早出处，或放弃这一路。
- 三件套始终对不上 → 这不是同一个人，写进「排除项」。

## 五、把查询本身记下来

每条查询都记「查了什么、为什么查、结论是什么」。报告里的「方法与局限」就靠这个，别人也能复现你的检索路径（`ledger` 的 `note` 字段够用）。

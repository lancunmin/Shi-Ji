# 案例：两种走法

一个信息充足的公开人物，一个线索稀疏的普通人。重点看**走法**和**怎么收尾**，别照抄结论。

---

## 案例 A · 公开人物（信息充足）

目标：核实 B站账号「罗翔说刑法」与本人身份，并整理公开资料。
线索：一个昵称 + 一个公开身份（中国政法大学教授）。

### 第一轮：广播

```bash
python scripts/shiji.py doctor
python scripts/shiji.py bili-user "罗翔" --limit 3
python scripts/shiji.py search "罗翔 中国政法大学" --limit 6
python scripts/shiji.py wx "罗翔 刑法" --limit 3
```

拿到的东西（节选，均为实际返回）：

- B站搜索三条：`罗翔说刑法`(mid 517327498, 粉丝 32180622, 签名「工作邮箱：x*******@hotmail.com」)、`罗翔`(mid 18243, 签名「我只是个天天被各种@的撞名的」)、`罗翔老师的哲学人生`(mid 323432471)
- 360 百科摘要：1977 年出生，湖南耒阳人，中国政法大学刑事司法学院教授、博导、刑法学研究所所长
- 公众号三篇：`罗翔 | 很遗憾,刑法跟你关系大了!`（2040书店，2020-08-01）、`罗翔说刑法!法外狂徒张三的传奇一生`（南方周末，2021-03-29）、`罗翔:如何理解刑法中的非法?`（北大法律信息网）

**这一步就已经有消歧价值了**：三个同名账号里，只有 mid 517327498 的签名留了工作邮箱，另两个明确是路人号。旧做法在这一步会给三个都打 0.62——这就是它没用的原因。

### 第二轮：进内容层

- 用 `bili-space 517327498` 拿签名、粉丝、投稿数
- 用 `fetch` 打开公众号文章（正文是 JS 壳，抓到的是空壳 → 记「未获取」，转人工）
- 摘要里出现「2020 年 3 月入驻 B站，两天粉丝破百万」（南方周末文章摘要）

### 第三轮：pivot

| 拿到 | 追什么 | 结果 |
| --- | --- | --- |
| 工作邮箱 | GitHub 提交记录、论文通讯作者 | 未在公开页找到匹配 |
| 教授身份 | 学校官网新闻、论文、讲座 | 与百科信息一致（多个独立来源） |
| 公众号作者 | 「罗翔说刑法」公众号 → 文章署名 | 与 B站账号同名，互证 |

### 报告节选

```markdown
## 一句话结论
B站账号「罗翔说刑法」（mid 517327498，粉丝 3218 万）与公开身份一致，
可信度：已核实（本人主页签名 + 多来源一致的机构信息）。

## 确认项
| 结论 | 依据类型 | 出处 | 原文摘录 |
| --- | --- | --- | --- |
| B站 mid 517327498 为本人账号 | A 本人自述 | space.bilibili.com/517327498 | 签名：工作邮箱：x*******@hotmail.com |
| 中国政法大学教授、刑法学研究所所长 | S 官方/机构 | 学校与百科页面 | 「刑事司法学院教授、博士生导师」 |

## 已排除
| 对象 | 依据 |
| --- | --- |
| mid 18243「罗翔」 | 签名自述「我只是个天天被各种@的撞名的」，粉丝 696 |
| mid 323432471「罗翔老师的哲学人生」 | 非本人运营，无任何指向性信息 |
```

### 这个案例教什么

1. **同名消歧要在第一轮就做**，别等攒了一堆再分。
2. **B站签名是最高性价比的自我描述**。
3. **公众号正文抓不到就记「未获取」**，不要用标题编内容。

## 案例 B · 普通人（线索稀疏，含抬头墙）

> 虚构示例，用于演示走法。

目标：一个校园墙昵称「雾港信箱」，想确认是不是某校学生。
线索：昵称 + 一个 QQ 群号 725306418（来自 B站签名）。

### 走法

```bash
python scripts/shiji.py bili-user "雾港信箱"
# → 三个同名前缀账号：雾港信箱 / 雾港信箱1 / 雾港信箱2
#   其中「雾港信箱1」签名写着「粉丝群：725306418」
python scripts/shiji.py variants "雾港信箱"     # 生成 16 个变体
python scripts/shiji.py search "725306418"       # 直接搜群号
python scripts/shiji.py links "725306418" --out handoff.md   # QQ群资料页要登录 → 交人工
```

### 结论（诚实版）

```markdown
## 一句话结论
能确认「雾港信箱1」这个 B站账号的签名里公开写着 QQ 群 725306418；
群与学校的关系、群主身份均未证实（QQ 群资料页需登录，未获取）。

## 线索
- B站三个同名前缀账号（725306418 只出现在「雾港信箱1」的签名里）
- 群号 725306418 未在搜索引擎收录的页面中出现

## 未证实（下一步）
| 线索 | 建议 |
| --- | --- |
| 群号 725306418 | 用户在 QQ 里搜群，看群名/简介/群主 |
| 三个同名前缀账号 | 看历史投稿与评论互动，是否同一人大小号 |

## 局限
- 中文昵称在搜索引擎里被分词拆碎，命中率低
- B站关注/粉丝列表需登录，关系链未获取
```

### 这个案例教什么

1. **线索稀疏时，结论就该稀疏**。硬凑一个「疑似某校学生」是最坏的结果。
2. **昵称变体 + 群号**是这类目标唯一能扩的方向。
3. **「未获取」要写出来**，并给出下一步——这比编一个答案有用得多。

---

## 两个案例的共同点

- 都先 `doctor`，再决定用哪些源。
- 都在第一轮就做同名消歧。
- 卡住时都转人工清单，不硬闯。
- 报告里「已排除」和「未证实」都占了篇幅——**这两节才是可信度的来源**。
